# Code of Conduct

## Our Pledge

We are committed to fostering an open, welcoming, respectful, and inclusive community.

We pledge to make participation in this project a harassment-free experience for everyone, regardless of age, disability, ethnicity, gender identity, level of experience, nationality, personal appearance, race, religion, or sexual identity.

---

# Our Standards

Examples of behavior that contributes to a positive environment include:

- Being respectful and professional.
- Giving constructive feedback.
- Accepting feedback gracefully.
- Helping new contributors.
- Focusing on improving the project.
- Respecting different viewpoints.
- Communicating with empathy.

Examples of unacceptable behavior include:

- Harassment or discrimination.
- Personal attacks.
- Trolling or insulting comments.
- Publishing private information.
- Threats or intimidation.
- Deliberately disruptive behavior.
- Any conduct that creates an unwelcoming environment.

---

# Project Values

This project values:

- Clean code
- Honest discussions
- Constructive reviews
- Continuous learning
- Collaboration
- Professionalism

Technical disagreements are welcome.

Personal attacks are not.

---

# Communication Guidelines

When discussing code:

- Critique the implementation, not the contributor.
- Explain _why_ a change is recommended.
- Be open to alternative solutions.
- Assume good intentions.

---

# Pull Requests

Reviews should focus on:

- Correctness
- Readability
- Maintainability
- Performance
- Consistency with project architecture

Avoid subjective comments that do not improve the project.

---

# Issues

When opening an issue:

- Search existing issues first.
- Provide enough information to reproduce the problem.
- Keep discussions focused on the reported issue.
- Remain respectful during conversations.

---

# Documentation

Documentation contributions are welcome.

Examples include:

- Fixing grammar
- Improving examples
- Clarifying architecture
- Expanding guides
- Updating outdated information

---

# Enforcement

Project maintainers are responsible for enforcing this Code of Conduct.

Maintainers may:

- Request changes to discussions.
- Edit or remove inappropriate content.
- Close conversations that become unproductive.
- Restrict participation for repeated violations.

---

# Scope

This Code of Conduct applies to:

- GitHub Issues
- Pull Requests
- Discussions
- Documentation
- Code Reviews
- Project communication channels

---

# Guiding Principle

Always leave the project better than you found it.

This includes:

- Better code
- Better documentation
- Better discussions
- Better collaboration

Every contribution, regardless of size, is appreciated.
